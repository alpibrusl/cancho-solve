# solve: writing a model

`solve check < model.sol` checks a model; `solve expand < model.sol` prints it flat as JSON; `solve run [--relax] < model.sol` solves it: the LP, or by branch and bound when it has bool/int variables (`--relax` solves the relaxation; `--node-limit N` and `--iteration-limit N` bound the search and give status feasible or unknown with a bound and gap). A refusal is JSON on standard error with a rule tag and a position.

param n = 4;                       // a number, or [1, 2, 3] for an array (0-based)
var x[0..n] : bool;                // or: int LO..HI, real LO..HI; one or two index ranges, half-open
maximize total: sum i in 0..n: v[i] * x[i];   // a sum's body is one term; parenthesise a longer one
subject to
    cap: sum i in 0..n: w[i] * x[i] <= 15;
    forall i in 0..n: lim: x[i] <= 1;       // one constraint for each i, named lim[i]

`solve verify` re-checks a claimed solution without the search: `(cat model.sol; echo ---; solve run < model.sol) | solve verify [--tolerance T]`. Standard input is the model, a line holding exactly ---, then JSON: solve run's output, or {"x":{"x[0]":1,...},"objective":v} (objective optional). Exit 0 and status verified when every bound, integrality and row holds within the tolerance (default 1e-6) and the objective is the evaluated one; otherwise a refusal on standard error whose tag (solve.bound-violated, solve.not-integral, solve.row-violated, solve.objective-mismatch) is the first violation and whose violations member lists up to 10. It proves feasibility, not optimality.

Every variable needs bounds. Terms must be linear: a number times one variable; ranges, indices and bounds are constants.
Reserved and not built yet: all_different, cumulative, element.
